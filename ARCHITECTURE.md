# Architecture & Design System

How VESTRA, the storefront, is organized, and the rules that keep every page consistent. The visual reference is
`prototypes/woman_/woman8` (screen + `DESIGN.md`, "Monochrome Absolute"), which reproduces Farfetch's
listing pattern.

## Pages

The header's category bar follows Farfetch: Gifts & Party, New In, Brands, the five categories and Sale (in red).
In Kids it is browsed by age instead: Gifts, New In, Brands, Baby (0–36 months), Kids (2–12 years),
Teens (13–16 years), Sale.
Above the footer, on every page: service links (How to shop, FAQs, Need help?) and the newsletter band.
The header's person icon opens the sign-in dialog (Farfetch's pop-up); signed in, it becomes an account menu.
The globe (header, mobile menu, footer) opens *Language & region*: the region converts every price to its currency.


| Route | Component | What it is |
| --- | --- | --- |
| `/` | `HomePage` | Department chooser, editorial, brands, designers, New In |
| `/womenswear`, `/menswear`, `/kids` | `DepartmentPage` | The department hub (Farfetch's order): campaign, New in daily, Trending now, editorial + its pieces, shop by age (kids), categories, trending brands, more to explore. **One template for all three** |
| `/womenswear/items`, `/menswear/items`, `/kids/items` | `ProductListingPage` | Farfetch's `items.aspx`: filters, sort, grid, load more |
| `/womenswear/brands`, `/menswear/brands`, `/kids/brands` | `BrandsPage` | Trending brands + every designer A–Z with its piece count |
| `/wishlist` | `WishlistPage` | Saved pieces (per account), remove with Undo, filters, size + Add to bag, recommendations |
| `/search?q=` | `ProductListingPage` | The same listing across all departments |
| `/product/:id` | `ProductPage` | One PDP for every department |
| `**` | `NotFoundPage` | 404 |

The department routes are generated by `departmentRoutes()` in `app.routes.ts`, so every department gets the
same two pages. Route `data.department` and `:id` reach components as inputs (`withComponentInputBinding`).

Listing state lives in the URL: `?age=baby&category=bags&designer=Prada&edit=gifts&sale=true&sort=price-asc&q=…`. Any view can be shared,
bookmarked and restored with the back button.

## Folders

```text
src/app
  core/
    auth/         AuthService (session), AuthDialogService (which screen is open), validation rules
    locale/       LocaleService (language + region), REGIONS with currency and rate, formatMoney
    catalog/      CatalogItem model, DEPARTMENTS / CATEGORIES taxonomy, size runs
    services/     CatalogStore (the only product source), WishlistService, CartService
  shared/
    ui/           ProductCard, WishlistButton, SectionHeader, Breadcrumb, PageHero, DesignerCard, BrandStrip, TextField, …
    pipes/        price
    utils/        formatPrice
  layouts/
    public-layout/  SiteHeader, SiteFooter, the shell
      locale/       LocalePicker (@defer): the Language | Region drawer
      auth/         AuthDialog (@defer) + one component per screen: sign in, register, code, forgot, social
  features/
    home/ department/ listing/ brands/ product/ wishlist/ not-found/
```

Rules:

1. **Products come only from `CatalogStore`** (`src/assets/data/catalog.json`). Pages derive views with
   `computed()`. They never keep their own product arrays.
2. **Features don't import each other's internals.** What two features need belongs in `core/` (state and data)
   or `shared/` (UI). The exception is `listing.query.ts`, a pure module that department pages reuse for
   designer lists.
3. **Department-specific content is data, not templates.** Words and photography live in
   `features/department/data/department-content.ts`. Structure lives in one template.
4. **Tile images come from the catalog.** Category and designer tiles show their newest piece, so an image
   always matches what the link leads to.

5. **Auth goes through `AuthService` only.** Forms call it and render its `AuthResult`; nothing else reads the
   session keys in `localStorage`. To open the dialog, call `AuthDialogService.open(view)`.

## Catalog model

```ts
interface CatalogItem {
  id; title; brand; price; image; description;
  department: 'womenswear' | 'menswear' | 'kids';
  category: 'clothing' | 'shoes' | 'bags' | 'accessories' | 'jewelry';
  addedAt: string;   // ISO date: "Newest first" and "New In"
  badge?: string;    // e.g. "New Season"
  edits: ('gifts' | 'party' | 'winter' | 'heritage')[];  // curated edits across categories
  salePrice?: number; // on sale: what the customer pays (price stays the original)
  ageGroup?: 'baby' | 'kids' | 'teens'; // kids only: AGE_GROUPS (Baby 0–36 months, Kids 2–12, Teens 13–16)
}
```

`sizesFor(item)` gives the size run: IT sizes for clothing, EU for shoes; kids get the run of their age group (3M–24M, 4Y–12Y, 13Y–16Y; shoes 17–21, 28–34, 36–40 EU). Bags, accessories and
jewelry are one size.

## Product photography

- **Every photo must show the product it names.** When adding a product, check the image (no logos of other
  brands, no adult model on a kids item). `catalog.json` never reuses a photo for two products.
- **Size per context:** `sizedImage(url, width)` asks imgix (Unsplash) for the width the UI needs: cards 600px,
  product page 1200px. Other hosts pass through unchanged.
- **Generated gallery:** `galleryFor(url)` builds the product page gallery from one photo: the full view plus two
  focal-point zooms (`crop=focalpoint&fp-z`), the detail shots a luxury PDP shows.
- **Designer tiles** use `featureDesigner()`: the house's newest *clothing* piece first (then bags, shoes,
  accessories, jewelry), so a designer is never pictured by a wallet.

## Design system

Tokens and utilities live in `src/styles.css` (Tailwind v4 `@theme` + `@utility`). Tailwind v4 doesn't read
`tailwind.config.js`, so everything is defined in CSS.

### Tokens

| Token | Value | Utility |
| --- | --- | --- |
| `ink` | `#000000` | `text-ink`, `bg-ink`, `border-ink` |
| `canvas` | `#ffffff` | `bg-canvas`, `text-canvas` |
| `surface` | `#f5f5f5` | `bg-surface` (image placeholders, footer) |
| `line` | `#e5e5e5` | `border-line` |
| `muted` | `#767676` | `text-muted` (secondary text, breadcrumbs) |
| `error` | `#ba1a1a` | `text-error` |
| Font | Inter | `font-sans` (default) |

**The radius and shadow scales are removed.** `rounded-lg` or `shadow-md` don't exist, so the sharp, flat look
can't drift. `rounded-full` remains for functional circles only (the wishlist button, count badges).

## Adding things

- **A department:** add it to `Department` and `DEPARTMENTS`, to the size runs, to `DEPARTMENT_CONTENT`, and add
  `...departmentRoutes('path', 'id')`. The header, listing, PDP and breadcrumbs pick it up.
- **A category:** add it to `ProductCategory` and `CATEGORIES`. Tiles and filters only appear where products
  exist.
- **A product:** add it to `catalog.json`. It appears in its department, listings, search and recommendations.
